# 저녁 식탁

일주일 저녁 식단, 장보기, 냉장고를 한 화면에서 관리하는 로컬 웹앱(PWA).
모든 데이터는 **기기 안(localStorage)** 에만 저장됩니다. 서버도 계정도 없습니다.

## 파일 구성

| 파일 | 역할 | 고칠 일이 있나 |
|---|---|---|
| `index.html` | 뼈대. 헤더 + 화면 자리 + 스크립트 연결 | 거의 없음 |
| `styles.css` | 색·글자·레이아웃. 팔레트는 맨 위 `:root` 한 곳 | 색 바꾸고 싶을 때 |
| `data.js` | 기본 메뉴 46가지와 재료 단가 74개 | 앱 안에서 고칠 수 있으니 손댈 일 없음 |
| `app.js` | 화면 6개, 식단 생성, 장보기 계산, 예산, 별점 | 기능 추가할 때 |
| `manifest.webmanifest` | 앱 이름·아이콘·시작 화면. 홈 화면 설치의 근거 | 이름 바꿀 때 |
| `sw.js` | 서비스 워커. 오프라인 캐시. 파일을 고치면 맨 위 `V` 값을 올려야 새 버전이 반영됨 | 배포할 때마다 |
| `icons/icon-192.png`, `icon-512.png` | 홈 화면 아이콘 | 취향대로 |

PWA가 성립하려면 `manifest.webmanifest` + `sw.js` + 아이콘 두 개 + **HTTPS 주소** 이 네 가지가 필요합니다.

## 올리는 법

**Vercel** — 이 폴더를 그대로 올리면 끝입니다. 빌드 설정은 없음(정적 사이트).
```
npm i -g vercel
cd 이_폴더
vercel
```

**GitHub Pages** — 저장소에 올리고 Settings > Pages에서 브랜치를 지정합니다.

**설치** — 배포된 주소를 폰에서 엽니다.
- 아이폰: 공유 버튼 > 홈 화면에 추가
- 안드로이드: 주소창 옆 메뉴 > 앱 설치

설치하면 주소창 없이 앱처럼 뜨고, 비행기 모드에서도 열립니다.

## 워크플로우

```
        ┌─────────────── ① 이번 주 식단 ───────────────┐
        │  일요일에 버튼 한 번. 7일치가 정해짐          │
        │  국은 한 냄비가 2~3일을 덮도록 나눠 끓임       │
        └───────────────────┬──────────────────────────┘
                            │ 메뉴의 재료가 자동 집계
        ┌───────────────────▼──────────────────────────┐
        │ ② 장보기 — 냉장고에 있는 건 빠짐, 예산 표시  │
        └───────────────────┬──────────────────────────┘
                            │ 체크 후 [냉장고에 넣기]
        ┌───────────────────▼──────────────────────────┐
        │ ③ 냉장고 — 구입일부터 남은 날짜 계산          │
        │    지난 것은 [버림] → 기록에 남음              │
        └───────────────────┬──────────────────────────┘
                            │ 임박 재료는 다음 식단에 가산점
        ┌───────────────────▼──────────────────────────┐
        │ ④ 평일엔 홈 화면에서 오늘 저녁만 확인          │
        └───────────────────┬──────────────────────────┘
                            │ 주말에 [이번 주 기록에 저장]
        ┌───────────────────▼──────────────────────────┐
        │ ⑤ 지난 메뉴 — 요일별 별점                     │
        │    4~5점은 자주, 1~2점은 덜 나오게 됨         │
        └───────────────────┬──────────────────────────┘
                            └──→ 다시 ①
```

식단을 새로 짜면 지난주는 자동으로 [지난 메뉴]에 저장됩니다.

## 예산이 계산되는 방식

- 재료마다 단가가 있습니다. g 단위는 1g당, 나머지는 1단위당.
- **메뉴 원가** = 재료 단가 × 수량. 식구 수를 바꾸면 고기 양이 따라 바뀝니다.
- **요일별 금액** = 메인 + 곁들임 + (국 원가 ÷ 그 국을 먹는 날 수).
- **주간 예산** = 장보기에서 실제로 살 것의 합계. 냉장고에 있는 건 빠집니다.
- 된장·참기름 같은 **양념과 건조식품은 예산에서 제외**합니다. 한 끼 때문에 된장 한 통 값이 잡히면 숫자가 왜곡되기 때문입니다. 목록에는 그대로 뜨고 "예산 제외"라고 표시됩니다.
- 단가는 [메뉴 관리 > 재료 가격]에서 언제든 고칠 수 있습니다. 초기값은 대략적인 시세라 실제와 다릅니다.

## 백업

[메뉴 관리 > 백업] 에 있습니다.

**내보내기** — `저녁식탁-백업-2026-09-06.json` 파일을 내려받거나 클립보드에 복사합니다.
메뉴, 가격, 냉장고, 주간 기록, 별점, 설정이 모두 들어갑니다. 1~2KB 정도라 메일로 보내두기도 좋습니다.

**전체 복원** — 지금 데이터를 모두 지우고 백업 시점으로 되돌립니다. 기기를 바꿨을 때 씁니다.

**메뉴만 합치기** — 지금 데이터는 그대로 두고 메뉴와 가격만 더합니다. 이름이 같은 메뉴는 건너뜁니다.
백업 파일뿐 아니라 **메뉴만 담긴 배열**도 받습니다. 이런 형식이면 됩니다.

```json
[
  { "name": "애호박전", "kind": "main", "min": 20,
    "ing": [ { "n": "애호박", "q": 2, "u": "개", "c": "채소" } ],
    "s": ["도톰하게 썬다", "부침가루 입혀 부친다"] }
]
```

`kind` 는 `soup` / `main` / `side`, `u` 는 앱의 단위 목록, `c` 는 분류입니다.
빠지거나 틀린 값은 기본값으로 채워지니 대충 적어도 들어갑니다.

주간 기록이 3주 넘게 쌓였는데 한 달 이상 백업하지 않으면 첫 화면에 조용히 한 줄 뜹니다.

## 국을 나누는 규칙

요일을 못박지 않습니다. 외식 날을 뺀 "국을 먹는 날"을 세어서 2~3일씩 균등하게 나눕니다.

- 국 먹는 날 6일 → 3일 + 3일 (두 번 끓임)
- 7일 → 3일 + 2일 + 2일 (세 번)
- 5일 → 3일 + 2일 (두 번)

외식을 화요일로 옮기든 목요일로 옮기든 **한 끼만 먹고 버려지는 냄비가 생기지 않습니다.**
냄비를 처음 끓이는 날이 주말이면 미역국·닭곰탕 같은 든든한 국을,
평일이면 25분 안쪽으로 끝나는 국을 고릅니다.
